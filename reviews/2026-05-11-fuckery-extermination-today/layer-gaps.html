A Rust optimizer is a configured value that drives a typed run graph by proposing changes to artifacts, requesting assessments, interpreting evidence through preference relations, and maintaining live populations, while the engine provides budgeted, observable, capability-scoped execution. — initial_library.md §29 · final design thesis

reading of the audit tree

The crate graph is mostly in the right shape. The vocabulary exists. The cold-core thesis above is implementable on the substrate that's been built. What's missing is not a layer — it's load-bearing contracts behind layer names that already look done.

Each layer is failing the same way: a builder shell, a public name, or a default prelude is doing the work of a contract. Reflection is a fixed-edit fixture. Scoring is a sync closure returning f64 + String. Cases are vector positions. Cache is a wrapper users compose. The engine has the right finalizers — and right beside them, public bypasses.

This document reads each layer against its spec, then sums the deltas as one honest reading of distance to the vision.

layer · 01

The ordinary user.

maturity · 27 / 100

Give Leaven a candidate, training work, a scoring function, an optimizer, and a budget. Optionally validation/test. Get a result back. Don't learn engine internals.

what is real

  • optimize(seed) builder shell with .train/.validation/.test/.runner/.score/.using/.budget/.on_event/.store/.run
  • required-budget & required-scorer pre-run refusals
  • train/validation/test lower into engine partitions with TrustPolicy::hide_from_proposers
  • leaven-lm exposes a provider-neutral async Lm trait
  • OptimizeStore can carry checkpoint persistence (engine-side)
  • engine emits StopReason and optional best (engine-side)

what is a proxy

  • Runner = Fn(&A, &C) → RunOutput — sync. cannot host LM/agent/subprocess honestly
  • Score = f64 + String + Vec<(String, String)> — no metrics, attachments, refs, errors
  • ScoreContext is three public fields, not an accessor view; no trace/history/budget access
  • cases are positional CaseId::from_index; user-stable ids only exist in leaven-eval unused by builder
  • no single-task / no-dataset mode; the default C = () path lowers to an empty case set, not EvaluationSet::Unscoped
  • ScoringEvaluator hard-codes CachePolicy::Never; no runtime-role config for solver / reflector / judge
  • OpenAiLm::from_env accepts a default_model argument and ignores it
  • OptimizeResult requires best, clones artifacts, drops stop reason; missing averages become 0.0
  • leaven::prelude exports RunContext, RunGraphView, TrustPolicy, EvaluationRequest, Population, Proposer, Evaluator, CachePolicy beside ordinary names
  • canonical proof p8_aime_gepa uses fixed-edit reflector; live solver shells out to a Python script calling OpenAI directly with urllib

layer · 02

The GEPA customizer.

maturity · 22 / 100

Touch surface, parent selection, part selection, batch sampling, reflection, acceptance, validation, population/frontier, merge, and stopping. Do not fork the engine.

what is real

  • Gepa optimizer with a real candidate/evaluate/accept loop and partial checkpoint round-trip
  • EditSurface in leaven-surface is healthy — typed part ids, addresses, views, edits, fingerprints, pure change_part
  • TournamentPopulation with pairwise Bradley-Terry state exists (in leaven-population)
  • engine has the right substrate: async Proposer<P>, typed request, ProposalContext, RunContext::propose
  • checkpoint covers the reduced slot set (selector cursor + frontier membership)

what is a proxy

  • ReflectiveMutation is a deterministic fixed-edit fixture with a production name; stores one edit, ignores artifact, surface, part
  • SurfaceProposer is sync and receives only artifact, surface, part. no assessments, no evidence, no traces, no part view, no objective
  • builder exposes only surface, optional population, reflector — 3 of 11 spec'd slots
  • GEPA bypasses RunContext::propose — calls record_proposal_batch directly with a hard-coded Cost::metric_calls(1)
  • evidence collapsed to scalar before reflection: ScoredFeedbackEvidence projects to ScalarEvidence; Gate(f64, f64)
  • ValidationPolicy is a marker trait with empty markers; FullValidation, MinibatchThenValidation have no behavior
  • MergeScheduler, GepaConfig, SystemAwareMerge, ReflectiveMutationConfig are placeholder structs
  • ParetoFrequencyWeighted selects deterministic best, not stochastic frequency-weighted Pareto sampling
  • public name is CandidateSelector; spec says GEPA-facing name is ParentSelector
  • train partition hard-coded to TRAIN; no BatchSampler slot; no Stopper slot
  • WorstEvidencePart is a placeholder with no evidence input

layer · 03

The optimizer author.

maturity · 48 / 100

Implement a new optimizer over Optimizer<P> and RunContext. Pairwise tournament, MIPRO, TextGrad, AlphaEvolve must not have to contort into GEPA's loop shape.

what is real

  • RunContext::propose finalizer: dispatches proposer, charges budget, records graph, emits events, checkpoints
  • RunContext::evaluate/evaluate_with finalizers: trust check, set resolution, cache lookup, evaluator dispatch, evidence storage, assessment recording, completion event
  • ProposalContext, EvaluationContext, RenderContext, MaterializeContext with scoped graph views + budget handles
  • EvidenceStore + RunContext::assessment_evidence for typed payload
  • BudgetLedger + BudgetHandle + sub_stage for attributed charges
  • PreferenceRelation<P> + Population<P> traits, graph-backed
  • pairwise & listwise assessment targets recorded in graph
  • casewise + pairwise evidence starts in leaven-evidence

what is a proxy

  • raw stage-context factories proposal_context, evaluation_context, render_context, materialize_context are public — optimizer authors can skip every finalizer
  • no RunContext::render_with / materialize_into finalizer — render & materialize cost can be invisible to budget, events, checkpoints
  • TrustPolicy::check_evaluation_request walks the unresolved EvaluationSet expression — EvaluationSet::Cases([test_id]) bypasses hidden-partition policy
  • EvaluationCacheKey omits request fingerprint, request kind, granularity, purpose, pair-order policy, listwise grouping, assessment shape — semantically distinct evaluations collide
  • cache hits return cached assessment ids for the new request id with zero recorded reuse linkage — request N can appear to own assessments from request M
  • ProposalContext has no evidence reader; only RunContext::assessment_evidence can load payloads — proposer stages see refs but cannot load
  • leaven-eval missing planned plan/request/traits/suite modules; leaven-run doing dataset/split/report lowering inline
  • P::Evidence fixed to CasewiseEvidence<ScoredFeedbackEvidence> in leaven-run; placeholder evidence vocabulary in leaven-evidence root exports
  • typed errors broad — ProposalError::Message, EvaluationError::Message instead of unsupported-granularity / shape-mismatch / trust-refused / cache-key-refused / attachment-failed
  • no public-contract proof: scalar keep-best, pairwise tournament, reflective evidence-driven proposer, agentic materializing stage — none of these exist as Layer-3 contract tests

correction order

The shortest path that doesn't re-validate the proxy.

The audit's implementation sequence is ordered to remove false public proof before new contracts are added — otherwise each new builder method gets validated by the same proxy example that hides the gap.

phase · 0

Quarantine false public proof.

Rename fixed-edit fixtures out of production names. Strip derive and gepa from default features until real. Remove placeholder provider/backend exports. Mark proxy examples as demos.

exit · no ordinary import or example claims a contract it can't honor.
phase · 1

Restore Layer 1 product builder truth.

Async runner / scorer. Rich Score + accessor ScoreContext. Stable cases. Single-task mode. Runtime / cache by role. Ordinary prelude split from advanced. Reports preserve absence and stop reason.

exit · mock-LM AIME-shaped run uses the same builder a live OpenAI run uses.
phase · 2

Seal engine & eval invariants.

Raw stage contexts become private. Render / materialize finalizers on RunContext. Trust enforced on resolved membership. Cache key carries full request semantics + graph-visible reuse. leaven-eval owns dataset / split / plan / suite / report.

exit · pairwise tournament implements over public primitives without new traits.
phase · 3

Restore GEPA as one honest optimizer.

Real ReflectiveMutation request: parent, part view, assessment ids, casewise evidence, attribution, lineage, budget, LM/agent role. All slots reachable through the builder. Proposal routed through engine finalization.

exit · mock-LM reflective GEPA improves an artifact by reading feedback.
phase · 4

Topology & placeholder hardening.

Delete or hard-cut leaven-dsrs. Topology rejects orphan dirs & unledgered exports. Provider/backend features cannot expose inert symbols. Crate roots are curated module maps, not file layouts.

exit · green topology means the public surface tells the truth.
phase · 5

Re-run the original pressure tests.

Scalar keep-best · pairwise tournament with fitted population · GEPA parity with real reflection · agentic Git/skill artifact with materialization, evidence store, trust boundaries, final-test policy.

exit · a new paper compiles & runs over public primitives without touching core.

What is true today,
and what becomes true
when this is paid.

Today. The architecture is sound. The crate boundaries are mostly right. The engine has the right finalizers. EditSurface, EvidenceStore, BudgetLedger, TournamentPopulation, and the Workspace trait all exist as real code. leaven-lm + leaven-lm-cache + leaven-lm-openai can compose into a real provider-neutral runtime — they just don't, in the canonical example.

After phase 0–2. A user can write the spec's eight-line builder and have it mean what it says. A non-GEPA optimizer like pairwise tournament fits over the public primitives. Hidden test cases stay hidden through resolved membership. Cache cannot silently swap one assessment for another.

After phase 3–5. GEPA reads selected feedback through Leaven LM/cache, produces a typed proposal with InfoRef::Assessment provenance, and routes through RunContext::propose. AIME's live and mock paths differ only by a provider construction line. A new paper compiles against public primitives without touching leaven-core.

"The engine is dumb. The optimizer is smart. The types tell the truth." Today, two of three. The audit is the receipt for the third.
